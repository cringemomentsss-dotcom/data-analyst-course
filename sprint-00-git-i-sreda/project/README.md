# Проект спринта 0. Репозиторий курса

## Задача

Собрать публичный репозиторий, в котором ты проведёшь следующие семь месяцев, и убедиться, что он работает у постороннего человека.

## Что сделать

1. **Создать репозиторий** `da-course` (или другое имя) в своём аккаунте GitHub, публичный.
2. **Инициализировать локально** папку `resources/da-course` и привязать к нему.
3. **Собрать структуру**: `db/`, `sprint-XX-.../`, `projects/`. Пустые папки Git не хранит — положи в каждую `.gitkeep` или README.
4. **Написать корневой README.** Что это, зачем, из чего состоит, как запустить окружение с нуля. Пиши для человека, который зашёл по ссылке из твоего резюме и знает о тебе ровно ничего.
5. **Настроить `.gitignore`** — данные, секреты, `.venv`, чекпойнты ноутбуков, `.DS_Store`.
6. **Поднять окружение**: `make db`, проверить `make check`.
7. **Настроить `nbstripout`** для репозитория.
8. **Перенести решения задач из курса SQL** в `sprint-00-git-i-sreda/solutions/` — те, что уже решал в августе. Если решений нет в файлах, реши десяток заново на новой базе: это заодно проверит, что база поднялась правильно.
9. **Сделать минимум 5 осмысленных коммитов** и отправить.

## Критерии приёмки

Обязательные:

- [ ] Репозиторий публичный, ссылка открывается.
- [ ] README объясняет проект человеку со стороны: что это, что внутри, как запустить. Комментарий-заглушка сверху убран, вместо него твой текст.
- [ ] `git clone` + `make db` на чистой машине поднимает базу. Проверь мысленно по шагам: не осталось ли чего-то, что есть только у тебя локально.
- [ ] `.gitignore` покрывает данные, секреты, `.venv`, `.ipynb_checkpoints`, `.DS_Store`.
- [ ] В репозитории нет ни одного файла тяжелее 10 МБ и ни одного секрета — ни в рабочем дереве, ни в истории.
- [ ] Минимум 5 коммитов, у каждого сообщение говорит, что изменилось по существу. `init`, `fix`, `update` не считаются.
- [ ] `nbstripout` установлен, проверен на тестовом ноутбуке.
- [ ] `make check` выводит 15 таблиц и четыре контрольных числа, все сходятся.

Желательные:

- [ ] В README есть бейдж или строка со стеком курса.
- [ ] История линейная, без merge-коммитов вида «Merge branch 'main' into main».
- [ ] Есть ветка, слитая в main — чтобы навык работы с ветками был не только на словах.

## Как сдать

Прислать ссылку на репозиторий. Я смотрю по списку выше и возвращаю с пометками по каждому пункту: принято / доработать / обсудить.

## Сколько это займёт

3–4 часа, если Docker уже стоит. День, если ставить с нуля и упереться в свободное место на диске.
