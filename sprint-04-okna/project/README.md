# Проект спринта 4. Онлайн-игра «Секреты Темнолесья»

## Постановка

Проект с ревью. Отличие от предыдущих: **список вопросов не выдан**. Есть контекст и цель, вопросы формулируешь сам — как это и происходит в работе.

Контекст. Мид-кор мобильная игра, монетизация через внутриигровые покупки: косметика, бустеры, валюта, боевой пропуск, наборы. Работает с сентября 2025. Продюсер ставит задачу так:

> «Через месяц защищаю бюджет на следующий год. Нужна картина монетизации: кто платит, сколько, за что, откуда эти люди приходят и что происходит с ними дальше. И ответ на вопрос, стоит ли нам вкладываться в удержание или лучше в привлечение.»

## Данные

Схема `game`. Поднять:

```bash
make game
```

| Таблица | Строк | Зернистость |
|---|---|---|
| `players` | 12 000 | игрок |
| `items` | 60 | предмет |
| `promo_codes` | 5 | промокод |
| `sessions` | 254 611 | игровая сессия |
| `levels` | 133 770 | достижение уровня |
| `purchases` | 7 966 | покупка |

Период: сентябрь 2025 — июнь 2026.

Что стоит знать заранее:

- `purchases.status = 'refunded'` — возврат, в выручку не входит.
- `purchases.price_paid` — фактически уплаченная сумма, уже со скидкой по промокоду.
- `promo_codes` содержит сроки действия. Данные соблюдают их не полностью.
- В `levels` нет первичного ключа.
- Схема тебе незнакома. Начни с разведки по восьми шагам из части 1 теории.

## Что сделать

**1. Разведка.** Пройди все восемь шагов. Результат — файл `explore.sql` с запросами и ответами в комментариях, плюс раздел в отчёте: что за данные, за какой период, какого качества.

**2. Сформулируй вопросы.** Минимум 12 вопросов, на которые ответишь. Они должны покрывать три темы, заданные продюсером: кто платит, за что платят, что с ними происходит дальше. Вопрос должен быть таким, чтобы на него можно было ответить числом.

Чтобы задать хороший вопрос, полезно заранее знать, что бывает интересно в такой игре:

- концентрация выручки (правило «мало кто платит много» — насколько оно здесь верно);
- сегментация плательщиков по сумме, частоте, давности;
- первая покупка: когда, за что, на каком уровне;
- интервалы между покупками и как они меняются;
- разница между каналами привлечения по качеству, а не по объёму;
- жизненный цикл: сколько живёт игрок, когда платит, когда уходит;
- прогресс по уровням и его связь с платежами;
- возвраты и промокоды: кто, сколько, не разъедают ли выручку.

**3. Ответь на них.** Обязательно использовать: ранжирующие функции, смещения (`LAG`/`LEAD`), нарастающий итог или скользящее среднее, `NTILE` или `PERCENT_RANK` для сегментации, перцентили.

**4. Проверь качество данных** и оцени, что из найденного искажает выводы.

**5. Ответь на вопрос продюсера** про удержание против привлечения. Это вопрос о деньгах: сравни, сколько выручки приносит удержание существующих игроков и сколько — привлечение новых, и что дешевле. Если данных для полного ответа не хватает — скажи, чего именно не хватает.

## Что сдать

1. `explore.sql` — разведка с ответами в комментариях.
2. `solution.sql` — запросы, сгруппированные по темам, с вопросом в комментарии перед каждым.
3. `README.md` — отчёт для продюсера: ответ на его вопрос первым экраном, дальше обоснования, в конце ограничения.

## Критерии приёмки

Обязательные:

- [ ] Разведка проведена и задокументирована до содержательных запросов.
- [ ] Сформулировано минимум 12 собственных вопросов, на каждый есть ответ числом.
- [ ] Определения зафиксированы: что считаем плательщиком, выручкой, активным игроком, оттоком.
- [ ] Возвраты исключены из выручки. Задвоенные покупки обработаны.
- [ ] Использованы все пять групп оконных функций из списка выше.
- [ ] Для распределений с хвостом (сумма покупок, LTV, длительность сессий) приведены медиана и перцентили, не только среднее. Разница объяснена словами.
- [ ] Сегментация плательщиков сделана количественно (`NTILE` или `PERCENT_RANK`), а не на глаз.
- [ ] Найдены минимум 3 дефекта данных, по каждому — оценка влияния.
- [ ] Есть санити-чек: сумма выручки по разрезам сходится с общей.
- [ ] Каналы сравниваются по качеству игрока, а не только по объёму. Доля плательщиков внутри канала, а не доля канала среди плательщиков.
- [ ] Ответ на вопрос продюсера однозначен и подкреплён цифрами.
- [ ] Раздел «ограничения» есть и содержателен.

Желательные:

- [ ] Задача «острова и промежутки» применена хотя бы раз (например, серии дней активности).
- [ ] Есть вывод, которого продюсер не ожидал.
- [ ] Оценка потенциала хотя бы одной рекомендации в деньгах.

## На что обратить внимание

Данные устроены так, что несколько очевидных на первый взгляд выводов при проверке разваливаются. Если какой-то результат тебя удивил — прежде чем писать его в отчёт, проверь другим способом. Правило: **вывод, который меня удивил, я перепроверяю дважды.**

И отдельно про каналы. Самый крупный по числу игроков канал почти наверняка не самый лучший. Сравнение каналов по объёму привлечения — типичная ошибка, из-за которой бюджеты годами уходят не туда.
