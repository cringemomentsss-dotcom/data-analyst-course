## Часть 1. Зачем Python, если есть SQL

Честный ответ: для большинства повседневных задач аналитика SQL достаточно, и питон ради питона писать не надо. Но есть пять вещей, которые SQL не умеет или умеет плохо:

1. **Статистика.** Проверка гипотез, доверительные интервалы, регрессия. В SQL этого нет (кроме ClickHouse, где кое-что есть).
2. **Данные не из базы.** API, JSON, выгрузки рекламных кабинетов, файлы от коллег.
3. **Итеративная логика.** Всё, где результат шага зависит от предыдущего: симуляции, бутстрап, обход дерева.
4. **Визуализация для исследования.** Двадцать графиков за десять минут, чтобы посмотреть на данные.
5. **Воспроизводимый анализ как документ.** Ноутбук, который через полгода можно перезапустить и получить те же цифры вместе с текстом рассуждений.

Разделение труда на практике: **тяжёлая агрегация — в SQL, всё остальное — в Python.** Тащить сто миллионов строк в pandas, чтобы сгруппировать их по дате, — плохая идея; база сделает это быстрее и без переполнения памяти.

## Часть 2. Синтаксис

### 2.1. Переменные и типы

```python
orders = 1240              # int
revenue = 84200.50         # float
city = "Тбилиси"           # str
is_active = True           # bool
missing = None             # NoneType
```

Тип не объявляется, но существует. `type(revenue)` вернёт `float`. Питон **динамически типизирован** (тип определяется значением), но **строго типизирован** (`"2" + 2` — ошибка, а не 4 и не "22").

Про имена: `snake_case`, латиница, осмысленно. `df2`, `tmp`, `x1` — то, за что на ревью возвращают. `delivered_orders` длиннее, чем `do`, и это правильно: код читают чаще, чем пишут.

### 2.2. Отступы — это синтаксис

В питоне блок задаётся отступом, а не скобками. Четыре пробела, не табы. Смешивание табов и пробелов — ошибка, которую глазами не видно.

Настрой редактор: показывать пробелы, заменять таб на четыре пробела. Один раз, и проблема исчезнет навсегда.

### 2.3. Числа

```python
7 / 2       # 3.5   — обычное деление, всегда float
7 // 2      # 3     — целочисленное
7 % 2       # 1     — остаток
2 ** 10     # 1024  — степень
round(3.14159, 2)   # 3.14
```

Обрати внимание: в питоне `7 / 2` даёт 3.5, а не 3. Это отличие от SQL, где целочисленное деление — ловушка. Здесь ловушка обратная: `//` иногда нужен, а пишут `/`.

Про `float`: та же проблема точности, что в SQL. `0.1 + 0.2 == 0.3` → `False`. Для денег в серьёзном коде берут `decimal.Decimal`; в аналитике обычно достаточно округлять результат и не сравнивать float на равенство.

### 2.4. Строки

```python
name = "  Иван   Петров "
name.strip()              # 'Иван   Петров' — обрезать по краям
name.lower()              # привести к нижнему регистру
" ".join(name.split())    # 'Иван Петров' — свернуть двойные пробелы
"1400 р.".replace(" р.", "")
"01.03.2026".split(".")   # ['01', '03', '2026']
"цена" in "цена товара"   # True
f"Выручка: {revenue:,.2f}"  # f-строка с форматированием
```

Приём `" ".join(s.split())` стоит запомнить: `split()` без аргументов режет по любому количеству пробелов, `join` собирает через один. Это самый короткий способ нормализовать пробелы.

Строки **неизменяемы**: `name.strip()` не меняет `name`, а возвращает новую строку. Забыть присвоить результат — классическая ошибка.

## Часть 3. Коллекции

### 3.1. Четыре типа и когда какой

| Тип | Запись | Упорядочен | Изменяем | Дубликаты | Когда |
|---|---|---|---|---|---|
| список | `[1, 2, 3]` | да | да | да | последовательность данных |
| кортеж | `(1, 2, 3)` | да | нет | да | запись фиксированной формы, ключ словаря |
| множество | `{1, 2, 3}` | нет | да | нет | уникальные значения, проверка вхождения |
| словарь | `{"a": 1}` | да (с 3.7) | да | ключи уникальны | сопоставление ключ → значение |

### 3.2. Список

```python
prices = [1400, 2100, 900]
prices[0]        # 1400 — первый
prices[-1]       # 900  — последний
prices[1:]       # [2100, 900] — срез
prices.append(1600)
prices.sort()                      # меняет список на месте, возвращает None
sorted(prices, reverse=True)       # возвращает новый список
sum(prices), len(prices), max(prices)
```

Ловушка, на которой спотыкаются все: `prices.sort()` возвращает `None`. `x = prices.sort()` даст `None`, а не отсортированный список. Правило: **методы, меняющие объект на месте, возвращают `None`.**

### 3.3. Множество — недооценённый инструмент

```python
paid = {1001, 1002, 1003}
active = {1002, 1003, 1004}

paid & active     # {1002, 1003} — пересечение (INTERSECT)
paid - active     # {1001}       — разность (EXCEPT)
paid | active     # объединение (UNION)
1001 in paid      # True, и это быстро
```

Это ровно операции над множествами из спринта 3, только в питоне. И проверка `in` для множества выполняется мгновенно независимо от размера, а для списка — перебором. На тысячах элементов разница уже заметна.

Практический приём: если нужно проверять вхождение много раз — сначала сделай множество.

### 3.4. Словарь

```python
revenue_by_city = {"Тбилиси": 84200, "Батуми": 31500}

revenue_by_city["Тбилиси"]              # 84200, упадёт если ключа нет
revenue_by_city.get("Ереван")           # None, не упадёт
revenue_by_city.get("Ереван", 0)        # 0 — значение по умолчанию
revenue_by_city["Ереван"] = 22000

for city, value in revenue_by_city.items():
    print(city, value)

revenue_by_city.keys(), revenue_by_city.values()
```

`.get()` вместо квадратных скобок — привычка, которая избавляет от половины `KeyError`.

Приём накопления, который понадобится в половине задач:

```python
counts = {}
for row in rows:
    key = row["city"]
    counts[key] = counts.get(key, 0) + 1
```

Это `GROUP BY` руками. Именно это pandas потом сделает одной строкой, и именно поэтому полезно один раз написать самому.

## Часть 4. Условия и циклы

### 4.1. Условия

```python
if revenue > 100_000:
    grade = "высокая"
elif revenue > 50_000:
    grade = "средняя"
else:
    grade = "низкая"

status = "выполнена" if is_done else "отменена"    # тернарный оператор
```

Логика: `and`, `or`, `not` — словами, а не символами. Приоритет тот же, что в SQL: `not` → `and` → `or`, и скобки так же не роскошь.

Про `None`: проверять через `is`, а не `==`.

```python
if value is None:        # правильно
if value == None:        # работает, но так не пишут
if not value:            # ОПАСНО: 0, '', [], {} тоже дадут True
```

Последняя строка — частая ошибка в аналитике: `if not price` сработает и для отсутствующей цены, и для цены 0. А это разные вещи.

### 4.2. Циклы

```python
for row in rows:
    ...

for i, row in enumerate(rows):          # с индексом
for name, value in zip(names, values):  # параллельно по двум спискам
for i in range(10):                     # 0..9

while not done:
    ...
```

`break` — выйти, `continue` — к следующей итерации, `pass` — ничего не делать (заглушка).

Ловушка: **не менять список во время обхода.**

```python
for r in rows:
    if bad(r):
        rows.remove(r)     # часть элементов будет пропущена
```

Правильно — собрать новый список:

```python
rows = [r for r in rows if not bad(r)]
```

### 4.3. Списковые включения

```python
prices = [parse_price(r["cena"]) for r in rows]
valid = [p for p in prices if p is not None]
labels = ["дорого" if p > 1500 else "норма" for p in valid]
unique_masters = {normalize_name(r["master"]) for r in rows}      # множество
by_id = {r["id_zapisi"]: r for r in rows}                          # словарь
```

Читается как «взять то-то из того-то, где условие». Короче цикла и быстрее его.

Граница разумного: если включение не помещается в одну-две строки или содержит два `for` и три `if` — пиши обычный цикл. Читаемость важнее краткости.

## Часть 5. Функции

### 5.1. Своя функция

```python
def safe_div(a, b, default=None):
    """Деление, которое не падает на нуле."""
    if b in (0, None) or a is None:
        return default
    return a / b
```

`def`, имя, аргументы, двоеточие, тело с отступом. Первая строка в тройных кавычках — docstring, описание. Пиши его всегда: через месяц он тебе же и понадобится.

Аргументы со значением по умолчанию идут после обязательных. Вызывать можно позиционно (`safe_div(10, 0)`) или по имени (`safe_div(a=10, b=0, default=0)`) — второе читается лучше, когда аргументов больше двух.

### 5.2. Ловушка изменяемого значения по умолчанию

```python
def add_row(row, acc=[]):     # НЕ ДЕЛАЙ ТАК
    acc.append(row)
    return acc
```

Список создаётся **один раз** при определении функции, а не при каждом вызове. Второй вызов получит список с результатами первого. Правильно:

```python
def add_row(row, acc=None):
    if acc is None:
        acc = []
    acc.append(row)
    return acc
```

### 5.3. Зачем аналитику функции

Не «для красоты». Три причины:

1. **Один расчёт — одно место.** Если определение метрики поменялось, правишь одну функцию, а не восемь копий по ноутбуку.
2. **Проверяемость.** Функцию можно протестировать, кусок кода в середине ноутбука — нет. Ровно поэтому тренажёр этого спринта устроен как набор функций.
3. **Читаемость.** `median(prices)` понятно сразу; десять строк сортировки и деления — надо разбирать.

Практический признак, что нужна функция: **ты копируешь кусок кода второй раз.**

> **Задачи 14–18:** `conversion_funnel`, `fill_missing_dates`, `retention_day_n`, `parse_utm`, `safe_div`.

## Часть 6. Вложенные структуры и немного ООП

### 6.1. Список словарей

Основная форма табличных данных в питоне до pandas — и то, что возвращает `csv.DictReader`, и то, что приходит из API:

```python
rows = [
    {"master": "Иван Петров", "cena": 1400, "status": "выполнена"},
    {"master": "Тимур Аскеров", "cena": 2100, "status": "отменена"},
]
```

Обращение: `rows[0]["master"]`. Обход: `for r in rows: r["cena"]`.

Вложенность бывает глубже — словарь со списками словарей внутри. Это типичный ответ API:

```python
data = {
    "status": "ok",
    "items": [{"id": 1, "tags": ["a", "b"]}, {"id": 2, "tags": []}],
}
data["items"][0]["tags"][1]     # 'b'
```

Разбирать такое проще, если сначала посмотреть на структуру: `data.keys()`, потом `type(data["items"])`, потом `data["items"][0]`. По шагам, а не угадывая.

### 6.2. Классы — ровно столько, сколько нужно

Свои классы аналитику писать почти не приходится. Но понимать надпись в документации нужно, потому что вся работа с библиотеками — это работа с объектами.

```python
s = "  Иван "        # s — объект класса str
s.strip()            # strip — метод объекта
len(s)               # len — функция, принимающая объект
```

Различие метода и функции: метод вызывается **через точку от объекта** и знает про него; функция принимает объект аргументом. `df.mean()` — метод, `len(df)` — функция. Никакой глубины тут нет, но путаница «почему тут точка, а тут скобки» снимается один раз этим объяснением.

Атрибут — данные объекта, без скобок: `df.shape`, `df.columns`. Метод — действие, со скобками: `df.head()`. Если написать `df.head` без скобок, питон вернёт саму функцию, а не результат — и это ещё одна ошибка, которую увидишь в первый же день pandas.

## Часть 7. Ошибки

### 7.1. Как читать traceback

```
Traceback (most recent call last):
  File "script.py", line 42, in <module>
    total = sum(prices)
  File "script.py", line 30, in parse_price
    return float(s)
ValueError: could not convert string to float: 'уточнить'
```

Читать **снизу вверх**: сначала тип и текст ошибки (последняя строка) — это что случилось. Потом самая нижняя строка стека — это где случилось. Верхние строки — как до этого дошли.

Здесь: `ValueError`, не смог превратить `'уточнить'` в число, в функции `parse_price`, строка 30. Всё, что нужно, есть в трёх строках.

Типичные ошибки и что они означают:

| Ошибка | Что случилось |
|---|---|
| `KeyError: 'city'` | нет такого ключа в словаре |
| `IndexError` | обращение за границу списка |
| `TypeError` | операция над несовместимыми типами, часто `None` |
| `ValueError` | тип подходит, значение нет |
| `AttributeError` | нет такого метода или атрибута; часто у `None` |
| `IndentationError` | сбитые отступы |
| `NameError` | переменная не определена, часто опечатка |

`TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'` — самая частая ошибка в аналитике. Означает: в данных пропуск, а ты его не обработал.

### 7.2. try / except

```python
try:
    value = float(raw)
except ValueError:
    value = None
```

Ловить конкретную ошибку, а не всё подряд. `except:` без указания типа проглотит и опечатку в имени переменной, и прерывание с клавиатуры — и ты будешь час искать, почему скрипт «молча не работает».

Когда использовать: там, где ошибка ожидаема и есть осмысленное поведение. Разбор грязного поля — да. Отсутствие файла — да. Скрывать ошибку в расчёте метрики — нет: пусть падает, это лучше, чем неверная цифра.

## Часть 8. Файлы и CSV

### 8.1. Чтение

```python
import csv

with open("data.csv", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))
```

`with` закрывает файл сам, даже если внутри случилась ошибка. Без него файл останется открытым.

`encoding="utf-8"` указывать всегда. Без него питон возьмёт кодировку системы, и на другой машине код упадёт. Если файл из Excel, часто нужен `utf-8-sig` — он съедает BOM в начале.

`csv.DictReader` даёт список словарей с ключами из первой строки. Все значения — **строки**: `row["cena"]` вернёт `'1400'`, а не `1400`. Приведение типов — твоя работа, csv не угадывает.

Почему не `line.split(",")`: в данных бывают запятые и кавычки внутри значений (`"Иванов, Иван"`), и ручной разбор их сломает. Модуль `csv` знает правила.

### 8.2. Запись

```python
with open("out.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["master", "revenue"])
    writer.writeheader()
    writer.writerows(rows)
```

`newline=""` обязателен — иначе на Windows между строками появятся пустые.
