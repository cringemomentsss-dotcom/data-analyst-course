# Итоговый проект модуля 4. Интернет-магазин BitMotion Kit

**1 неделя.** Проект, закрывающий модуль статистики. Первая половина — метрики на SQL, вторая — разбор A/B-теста на Python. Связка, которая и есть повседневная работа продуктового аналитика.

## Постановка

BitMotion Kit — интернет-магазин аксессуаров для техники, работает в восьми странах Европы. Полгода назад команда сделала новую версию сайта и восемь недель тестировала её на половине новых пользователей. Тест закончился, решение не принято.

Задачу ставит руководитель продукта:

> «Мне нужны две вещи. Первая — базовая картина по магазину: воронка, конверсии, чеки, активность. Мы всё это считаем по-разному в разных отчётах, хочу один согласованный набор цифр. Вторая — решение по тесту новой версии сайта. Команда говорит, что конверсия выросла на восемь процентов, и хочет раскатывать. Мне нужна проверка.»

Последняя фраза — суть задания. Ответ «да, выросла» и ответ «нет, не выросла» оба неверны.

## Часть 2. Разбор эксперимента

Ноутбук `ab_analysis.ipynb`.

8. Прочитать паспорт эксперимента. Выписать, что заявлено: гипотеза, единица, первичная метрика, окно, плановое соотношение.
9. **Валидация до анализа:** SRM, балансировка по устройству, стране, каналу.
10. Посчитать MDE при фактическом размере групп. Сравнить с эффектом, заявленным в гипотезе.
11. Первичная метрика: конверсия в покупку. Эффект абсолютный и относительный, доверительный интервал, p-value.
12. **Guardrail-метрики.** В паспорте их нет — определи сам. Минимум три, и одна из них обязательно должна быть про деньги на пользователя.
13. Проверить выручку на пользователя двумя способами: t-тестом и бутстрапом. Объяснить, почему здесь бутстрап уместен.
14. Разбор по сегментам с поправкой на множественность.
15. Решение: раскатывать / не раскатывать / доработать / перезапустить. Однозначное, с обоснованием.
16. Документ по результату эксперимента по структуре из части 6 спринта 12.

### Эксперимент exp_site_v2

Гипотеза из паспорта: новая версия сайта повысит конверсию в покупку **минимум на 10%**.

| | control | treatment |
|---|---|---|
| пользователей | 8 189 | 8 275 |
| покупателей | 547 | 601 |
| доля мобильных | 61,29% | 62,02% |

**SRM:** доля treatment 50,26%, χ² = 0,449, p = 0,503 → в порядке.
**Балансировка по устройству:** 61,29% против 62,02% → в порядке.

**Первичная метрика — конверсия в покупку:** 6,680% → 7,263%.
Абсолютный эффект **+0,583 пп**, 95% ДИ **[−0,195; +1,361]**, относительный лифт **+8,7%**, z = 1,469, **p = 0,142** → **не значимо**.
**MDE** при n = 8 189: **1,093 пп**, то есть **16,4% относительных**.

**Guardrail 1 — средний чек** (по доставленным заказам): 126,14 → 113,06, то есть **−10,4%**.
n = 496 / 547, t = 3,177, **p = 0,0015**, ДИ разницы **[−21,17; −5,00]** → **значимо хуже**.
Медианы: 109,84 → 94,76.

**Guardrail 2 — выручка на пользователя:** 7,640 → 7,473, то есть **−2,2%**.
t = 0,319, **p = 0,750**, ДИ разницы **[−1,192; +0,858]**. Бутстрап-интервал: **[−1,240; +0,825]** — практически тот же.

**Guardrail 3 — доля отмен и возвратов:** 9,32% против 8,99% → без изменений.

## Правильный вывод и почему он не очевиден

Здесь три разных неверных ответа, каждый из которых кто-нибудь даст.

**Неверный ответ №1: «Конверсия выросла на 8,7%, раскатываем».** Так говорит команда. Проблема: p = 0,142, интервал накрывает ноль. Наблюдаемый рост может быть шумом.

**Неверный ответ №2: «p = 0,142, эффекта нет, не раскатываем».** Формально аккуратнее, но тоже неполно. MDE теста — 16,4% относительных, а гипотеза заявляла минимум 10%. **Тест изначально не был способен подтвердить собственную гипотезу.** Отсутствие значимости здесь мало что говорит о продукте и много говорит о планировании.

**Неверный ответ №3: «Конверсия под вопросом, но чек упал значимо, значит новая версия хуже».** Ближе, но и это не главное. Средний чек сам по себе не метрика успеха: если конверсия выросла, а чек упал, итог зависит от произведения.

**Правильный ответ** требует посмотреть на **выручку на пользователя** — метрику, которая учитывает и то, и другое. Она изменилась на −2,2% с интервалом [−1,19; +0,86] на базе 7,64. То есть **тест не смог отличить «стало на 15% хуже» от «стало на 11% лучше»**.

Итог: **не раскатывать, но и не отвергать гипотезу.** Тест не дал информации, достаточной для решения. Рекомендация — перезапустить с правильно рассчитанной выборкой, взяв первичной метрикой выручку на пользователя, а не конверсию.

И отдельный вывод для процесса: если бы MDE посчитали до запуска, стало бы видно, что восьми недель мало, и восемь недель работы команды не были бы потрачены впустую.

## Критерии приёмки

Обязательные:

- [ ] Дубликаты заказов и событий найдены и обработаны; числа совпадают с эталонными.
- [ ] `metriki.md` заполнен: по каждой метрике формула, статусы, исключения, зернистость.
- [ ] Воронка посчитана по уникальным пользователям, значения совпадают с эталоном.
- [ ] Приведены и средний, и медианный чек; разница объяснена.
- [ ] Все метрики части 1 воспроизведены.
- [ ] SRM проверен первым, до анализа результата.
- [ ] Балансировка проверена минимум по трём признакам, зафиксированным до эксперимента.
- [ ] MDE посчитан и **сопоставлен с эффектом, заявленным в гипотезе**.
- [ ] Первичная метрика приведена с абсолютным эффектом, относительным лифтом и доверительным интервалом.
- [ ] Определены минимум три guardrail-метрики, одна из них — деньги на пользователя.
- [ ] Средний чек проверен и найдено значимое ухудшение.
- [ ] Выручка на пользователя проверена t-тестом и бутстрапом, результаты сопоставлены.
- [ ] Объяснено, почему решение нельзя принять только по конверсии.
- [ ] Решение однозначное, с рекомендацией по перезапуску и указанием правильной первичной метрики.
- [ ] Нигде не написано «эффекта нет» вместо «эффект не обнаружен».
- [ ] Сегментный анализ сделан с поправкой на множественность.
- [ ] Документ по эксперименту содержит раздел ограничений.
- [ ] Сводка для руководителя продукта понятна без статистических терминов, кроме доверительного интервала, и отвечает на его вопрос первым абзацем.
- [ ] Ноутбук перезапускается с нуля.

Желательные:

- [ ] Посчитан размер выборки, нужный для обнаружения эффекта 10% по конверсии, и срок по фактическому трафику.
- [ ] То же для выручки на пользователя — и показано, что там выборка нужна больше, потому что дисперсия выше.
- [ ] Проверено, объясняется ли падение чека сдвигом в структуре категорий или числе товаров в заказе.
- [ ] Проверен эффект по неделям: нет ли признаков эффекта новизны.
- [ ] Оценено в деньгах, чем обошлась бы ошибочная раскатка при годовом трафике.
- [ ] Найден дефект данных, не упомянутый в ТЗ.
