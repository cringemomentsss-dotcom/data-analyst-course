## Часть 1. Зачем аналитику вероятность

### 1.1. Главная мысль модуля

Ты посчитал конверсию за неделю: 26,6%. На следующей неделе — 24,9%. Упала?

Ответа из этих двух чисел не существует. Конверсия — не свойство продукта, а **наблюдение над выборкой**. Если через воронку прошла тысяча человек, наблюдаемая доля будет гулять примерно в пределах ±1,4 процентного пункта просто из-за того, кто именно в эту тысячу попал. Разница между 26,6 и 24,9 внутри этого шума.

Всё остальное в модуле — способы посчитать, где кончается шум.

### 1.2. Три вопроса, на которые отвечает вероятность

1. **Насколько вероятен наблюдаемый результат при обычном ходе дел?** Если очень маловероятен, значит дело не обычное.
2. **Какой разброс ожидать?** Сколько заявок придёт в худший день месяца, сколько операторов держать в смене.
3. **Какой размер выборки нужен, чтобы измерить с нужной точностью?** До эксперимента, а не после.

## Часть 2. Основы

### 2.1. Событие и вероятность

Вероятность — число от 0 до 1, доля исходов, в которых событие происходит. В продуктовых данных вероятность обычно оценивают частотой: конверсия 319 из 1 200 даёт оценку 0,266.

Слово «оценка» тут ключевое: истинная вероятность неизвестна, у нас есть выборочная оценка, и она отличается от истины на величину, которую можно посчитать. Это спринт 11.

### 2.2. Сложение и умножение

**Хотя бы одно из двух:**

```
P(A или B) = P(A) + P(B) − P(A и B)
```

Вычитать пересечение обязательно, иначе оно посчитается дважды. Для несовместных событий (не могут произойти вместе) пересечение равно нулю, и остаётся простое сложение.

**Оба сразу:**

```
P(A и B) = P(A) × P(B|A)
```

Для независимых событий `P(B|A) = P(B)`, и формула упрощается до произведения. Но **независимость надо обосновывать, а не предполагать**. В продуктовых данных события почти всегда зависимы: игрок, открывший кошелёк, гораздо вероятнее сделает депозит.

### 2.3. Условная вероятность

```
P(A|B) = P(A и B) / P(B)
```

Это то, чем аналитик занимается постоянно, даже не называя так. «Конверсия в депозит среди тех, кто открыл кошелёк» — это условная вероятность. Каждый шаг воронки — условная вероятность относительно предыдущего.

## Часть 3. Формула Байеса

### 3.1. Формула

```
P(A|сигнал) = P(сигнал|A) × P(A) / P(сигнал)
```

Она отвечает на вопрос: как меняется наше представление о вероятности события, когда пришла новая информация.

### 3.2. Пример, который надо прочувствовать

Антифрод-модель. Мошенников среди игроков 0,1%. Модель ловит 99% мошенников (чувствительность) и ошибочно срабатывает на 1% честных игроков.

Модель сработала. Какова вероятность, что перед нами мошенник?

Интуиция говорит «около 99%». Правильный ответ — **9%**.

Почему: из 100 000 игроков мошенников 100, модель поймает 99 из них. Честных 99 900, и на 1% из них модель сработает ошибочно — это 999 человек. Итого срабатываний 1 098, из них настоящих 99. Доля — 9%.

Причина в том, что **честных гораздо больше**, и даже маленькая доля ошибок на большой группе даёт больше срабатываний, чем почти идеальная точность на маленькой.

### 3.3. Почему это важно на практике

Отсюда следуют три вещи, о которые регулярно спотыкаются продуктовые команды:

- **«Точность 99%» ничего не значит без базовой частоты события.** Модель, предсказывающая отток с точностью 95%, при оттоке в 5% может быть хуже, чем правило «никто не уйдёт».
- **Скоринг редких событий требует очень низкого FPR.** Не высокой чувствительности, а именно низкого числа ложных срабатываний.
- **Порог классификации выбирается из цены ошибок**, а не ставится в 0,5 по умолчанию. Это тема модуля 7.

## Часть 4. Случайные величины

### 4.1. Что это

Случайная величина — величина, значение которой определяется случаем: размер депозита следующего игрока, число заявок за час, длительность сессии.

**Дискретная** принимает отдельные значения (число заявок: 0, 1, 2…). **Непрерывная** — любые значения в интервале (длительность, сумма).

### 4.2. Математическое ожидание и дисперсия

**Математическое ожидание** — среднее по всем возможным исходам с учётом их вероятностей:

```
E[X] = Σ значение × вероятность
```

Пример: игрок платит 0 с вероятностью 0,7, десять с вероятностью 0,25 и сто с вероятностью 0,05. Ожидаемая выручка — 7,5. Обрати внимание: **ни один игрок не заплатит 7,5.** Ожидание — характеристика распределения, а не предсказание для отдельного случая. Это то же различие, что между «средний чек 52» и «половина платит меньше 30».

**Дисперсия** — средний квадрат отклонения от ожидания:

```
Var[X] = Σ (значение − E[X])² × вероятность
```

Стандартное отклонение — корень из дисперсии, в тех же единицах, что величина.

В том же примере: ожидание 7,5, дисперсия 468,75, стандартное отклонение 21,6. Разброс втрое больше ожидания — типичная картина для денег.

### 4.3. Закон больших чисел

С ростом числа наблюдений выборочное среднее приближается к математическому ожиданию.

Практическое следствие: **метрика на маленькой выборке нестабильна, и это не баг данных.** Конверсия по каналу, приведшему 12 игроков, будет прыгать от недели к неделе, и никакие оптимизации на неё не влияют. Первый вопрос при виде скачущей метрики — не «что случилось», а «сколько там наблюдений».

## Часть 5. Дискретные распределения

### 5.1. Бернулли и биномиальное

**Эксперимент Бернулли** — одно испытание с двумя исходами: конвертировался или нет.

**Биномиальное распределение** — число успехов в n независимых испытаниях с вероятностью p:

```python
from scipy import stats
stats.binom.pmf(k, n, p)      # ровно k успехов
stats.binom.sf(k - 1, n, p)   # не менее k успехов
```

Параметры: `mean = n·p`, `var = n·p·(1−p)`.

**Это главное распределение продуктовой аналитики**, потому что любая конверсия — биномиальная величина. Из его дисперсии растёт стандартная ошибка доли, из неё — доверительные интервалы и все тесты пропорций.

Обрати внимание на `sf(k - 1)`, а не `sf(k)`: `sf` даёт «строго больше», а «не менее k» это «строго больше k−1». Ошибка на единицу здесь встречается постоянно.

### 5.2. Пуассон

**Распределение Пуассона** — число событий за фиксированный интервал, когда события происходят независимо со средней интенсивностью λ:

```python
stats.poisson.pmf(k, lam)      # ровно k
stats.poisson.sf(k - 1, lam)   # не менее k
```

Замечательное свойство: `mean = var = λ`. Один параметр описывает всё.

Что моделирует в продукте: заявки в поддержку за час, заказы в минуту, отказы платежей за день, посетители сайта за интервал.

**Практическое применение — планирование мощности.** Если в среднем приходит 10 заявок в час, то заявок будет ровно 10 далеко не всегда. Вероятность получить 15 и больше — 8,4%. То есть примерно в каждой двенадцатой смене операторов, рассчитанных на 10 заявок, не хватит.

Отсюда правило: **мощность планируется не по среднему, а по перцентилю.** «Держим столько операторов, чтобы справляться в 95% часов» — корректная постановка. «Держим по среднему» — гарантированные перегрузки в половине смен.

## Часть 6. Непрерывные распределения

### 6.1. Нормальное

```python
stats.norm.cdf(x, mu, sigma)    # P(X < x)
stats.norm.ppf(q, mu, sigma)    # квантиль
```

Правило сигм: ±1σ содержит 68% наблюдений, ±2σ — 95%, ±3σ — 99,7%. Точное значение для 95% — ±1,96σ, и это то самое 1,96 из доверительных интервалов.

**Где нормальное распределение действительно встречается:** ошибки измерений, суммы и средние многих независимых величин. Второе важнее первого — именно поэтому нормальное распределение вообще имеет значение для аналитика (см. центральную предельную теорему, спринт 11).

**Где НЕ встречается:** деньги, время, длительности, счётчики. Практически всё, что мы измеряем в продукте.

### 6.2. Логнормальное

Если логарифм величины распределён нормально, сама величина распределена логнормально. Признаки: только положительные значения, правый хвост, среднее заметно больше медианы.

В данных курса:

| Величина | Среднее | Медиана | Отношение |
|---|---|---|---|
| Успешный депозит, € | 52,02 | 29,92 | 1,74 |
| Ставка, € | 2,63 | 1,56 | 1,69 |
| Длительность сессии, сек | 873 | 491 | 1,78 |

Все три логнормальны, и это не совпадение: так устроено почти всё, что связано с деньгами и временем.

**Практическое следствие:** работать с логарифмом. Логарифм логнормальной величины нормален, а значит к нему применимы обычные методы — t-тест, доверительные интервалы, регрессия. Именно поэтому в A/B-тестах на выручку часто анализируют `log(revenue)`, а не саму выручку.

### 6.3. Экспоненциальное

Время между независимыми событиями. Если события пуассоновские с интенсивностью λ, промежутки между ними экспоненциальны со средним 1/λ.

Что моделирует: время между заявками, между депозитами одного игрока, до следующей сессии.

### 6.4. Как понять, какое распределение

Порядок действий:

1. **Гистограмма.** Форма видна сразу: симметричная, с хвостом, два горба.
2. **Среднее против медианы.** Заметная разница — хвост.
3. **Гистограмма логарифма.** Если стала симметричной — логнормальное.
4. **QQ-plot.** Точки на прямой — распределение подходит.
5. **Формальный критерий.** Шапиро — Уилк для нормальности.

```python
from scipy import stats
import numpy as np

stats.probplot(np.log(sample), dist="norm", plot=ax)   # QQ-plot
stats.shapiro(sample)                                   # критерий нормальности
```

Про формальные критерии одна оговорка: **на больших выборках они почти всегда отвергают нормальность.** При двадцати тысячах наблюдений даже крошечное отклонение даст p-value близкое к нулю. Поэтому решение принимается по картинке и по практическим соображениям, а критерий — вспомогательный аргумент. На выборках до нескольких сотен он полезен, дальше — смотри QQ-plot.

> **Задачи 7–9:** нормальное, логнормальное, проверка нормальности.

## Часть 7. Симуляция

### 7.1. Зачем аналитику Монте-Карло

Аналитическая формула есть не всегда. Формулы для доверительного интервала медианы, отношения двух метрик, сложной композитной метрики либо не существует, либо требуют предпосылок, которые не выполняются.

Симуляция работает всегда: генерируем данные с известными свойствами много раз и смотрим на распределение результата.

```python
rng = np.random.default_rng(42)
draws = rng.binomial(1000, 0.266, size=10_000) / 1000
draws.std()      # стандартная ошибка доли, полученная без формулы
```

### 7.2. Два применения

**Проверить себя.** Посчитал аналитически — подтверди симуляцией. Если расходятся, одно из двух неверно. Это самая надёжная проверка статистических расчётов, и её стоит делать всегда.

Проверка на данных курса: аналитическая стандартная ошибка доли при p = 0,266 и n = 1000 равна `sqrt(0.266 × 0.734 / 1000) = 0,0140`. Симуляция даёт 0,0140. Сходится.

**Ответить, когда формулы нет.** Бутстрап (спринт 11) — это и есть симуляция, применённая к имеющейся выборке.

### 7.3. Обязательное правило

**Всегда фиксируй seed.**

```python
rng = np.random.default_rng(42)     # правильно
np.random.seed(42)                  # устаревший способ, глобальное состояние
```

Причины две. Воспроизводимость: результат, который нельзя повторить, нельзя проверить. И отладка: без фиксированного seed невозможно понять, изменилась цифра из-за твоей правки или из-за случайности.

Локальный генератор `default_rng` лучше глобального `np.random.seed`, потому что не зависит от того, что происходило в других ячейках ноутбука.

## Часть 8. Размер выборки

Расчёт, который делают **до** сбора данных, и почти никогда не делают.

Для оценки доли с точностью ±MOE при уровне доверия conf:

```
n = z² × p(1−p) / MOE²
```

где z — квантиль нормального распределения (1,96 для 95%).

Практический пример: конверсия ожидается около 26,6%, хотим измерить с точностью ±2 процентных пункта. Нужно **1 876 наблюдений**.

Два свойства, которые надо прочувствовать:

- **Точность вдвое выше требует выборки вчетверо больше.** MOE входит в квадрате. Хотим ±1 пп — нужно 7 502 наблюдения.
- **Худший случай — p = 0,5.** При нём `p(1−p)` максимально. Если не знаешь ожидаемую долю, считай по 0,5 и получишь гарантированный запас.

Зачем это аналитику до A/B-тестов: чтобы отвечать на вопрос «сколько ждать» цифрой, а не «ну недельку». В спринте 12 к этому добавится мощность, и расчёт станет полным.
