# Проект спринта 12. Разбор трёх экспериментов

## Что это за задание

Проект с ревью и, пожалуй, самый интересный в курсе.

В базе курса с самого начала лежат три эксперимента. Ты видел их в дата-словаре со дня первого запуска `make db`, и там было написано: «каждый из трёх устроен по-разному, и это сделано намеренно; разбирать их будем в спринте 12».

Пора. Каждый требует разного вывода, и **два из трёх нельзя раскатывать** — но по совершенно разным причинам. Различить их — вся задача.

Дополнительная сложность: **паспорта экспериментов заполнены не полностью.** В таблице `experiments` есть гипотеза, единица, первичная метрика и окно. Чего там нет — размера выборки, MDE, заявленного уровня значимости, guardrail-метрик. Как будто эксперимент запускали, не спланировав. Так, к сожалению, чаще всего и бывает, и часть твоей работы — восстановить недостающее и оценить, чем это обошлось.

## Данные

Схема `casino`, таблицы:

- `experiments` — паспорта трёх экспериментов;
- `ab_assignments` — назначение варианта: `experiment_id`, `unit_id`, `variant`, `assigned_ts`;
- `visitors`, `page_events` — верхняя воронка (для экспериментов на посетителях);
- `users`, `deposits`, `events` — для эксперимента на игроках.

Ключевая тонкость: **`ab_assignments.unit_id` содержит идентификаторы разной природы.** Для `exp_001` и `exp_003` это `visitor_id`, для `exp_002` — `user_id`. Что именно — сказано в `experiments.unit`. Джойн без учёта этого даст мусор.

## Что сделать

Ноутбук `ab_analysis.ipynb`. По каждому из трёх экспериментов пройти полный цикл.

**Шаг 1. Восстановить дизайн.** Прочитать паспорт. Определить: единица рандомизации, первичная метрика (как её посчитать из событий), окно, фактический размер групп. Выписать, чего в паспорте не хватает.

**Шаг 2. Задать guardrail-метрики.** Их в паспорте нет — придумай сам, обоснуй. Для экспериментов на верхней воронке очевидный кандидат — конверсия дальше по воронке: тест мог поднять начатые регистрации, но привести мусорный трафик.

**Шаг 3. Посчитать MDE** при фактическом размере групп. Это надо было сделать до запуска; делаем сейчас, чтобы понять, что вообще можно было обнаружить.

**Шаг 4. Валидация.** SRM. Балансировка по устройству, стране, каналу. Целостность разметки. **До анализа результата.**

**Шаг 5. Анализ первичной метрики.** Эффект абсолютный и относительный, доверительный интервал, p-value.

**Шаг 6. Guardrail.**

**Шаг 7. Сегменты.** По устройству как минимум. С поправкой на множественность.

**Шаг 8. Решение.** Однозначное: раскатывать / не раскатывать / перезапустить. С обоснованием.

**Шаг 9. Документ** по структуре из части 6 теории — по каждому эксперименту.

Отдельно, вне трёх экспериментов:

**Шаг 10. Посчитать цену подглядывания** на данных `exp_001`: симуляцией показать, какой была бы фактическая доля ложных срабатываний, если бы аналитик смотрел на результат каждый день на протяжении четырёх недель.

## Эталонные результаты

Единица рандомизации `exp_001` и `exp_003` — посетитель; первичная метрика — доля посетителей, дошедших до события `signup_start`.

### exp_001 — onboarding_short_form

Окно 2 марта — 29 марта. Гипотеза: короткая форма регистрации (6 полей → 3) поднимет долю начатых регистраций минимум на 15%.

| | control | treatment |
|---|---|---|
| посетителей | 21 746 | 21 713 |
| `signup_start` | 761 | 963 |
| зарегистрировалось | 82 | 96 |
| доля десктопа | 28,52% | 28,02% |

**SRM:** доля treatment 49,96%, χ² = 0,03, p = 0,874 → в порядке.
**Балансировка по устройству:** 28,52% против 28,02% → в порядке.
**Первичная метрика:** 3,499% → 4,435%. Абсолютный эффект **+0,936 пп**, 95% ДИ **[+0,569; +1,303]**, относительный лифт **+26,7%**, z = 4,997, **p = 5,8 × 10⁻⁷**.
**MDE** при n = 21 746: **0,493 пп** (14,1% относительных) — эксперимент был спланирован адекватно, наблюдаемый эффект почти вдвое больше обнаружимого.
**Guardrail** (конверсия визита в регистрацию): 0,377% → 0,442%, z = 1,062, p = 0,288 → не пострадал.
**По сегментам:** мобильные 2,788% → 3,701% (+32,7%, p < 0,0001); десктоп 5,143% → 6,130% (+19,2%, p = 0,018). Эффект есть в обоих, направление одно.

**Вывод: раскатывать.**

### exp_003 — bonus_wheel

Окно 4 мая — 31 мая. Гипотеза: колесо бонусов на лендинге поднимет долю начатых регистраций.

| | control | treatment |
|---|---|---|
| посетителей | 23 455 | 24 418 |
| `signup_start` | 805 | 1 008 |
| зарегистрировалось | 106 | 133 |
| **доля десктопа** | **17,08%** | **38,22%** |

**SRM:** доля treatment 51,01%, χ² = 19,37, **p = 1,1 × 10⁻⁵** → **СЛОМАНО**.
**Балансировка по устройству:** 17,08% против 38,22%, разница 21,1 пп → группы несопоставимы.
**Первичная метрика (если считать наивно):** 3,432% → 4,128%, эффект +0,696 пп, ДИ [+0,355; +1,037], лифт **+20,3%**, **p = 6,7 × 10⁻⁵**.
**По сегментам:** внутри мобильных 3,160% → 3,246% (+2,7%, **p = 0,667** — ничего); внутри десктопа 4,244% → 5,433% (+28,0%, p = 0,004).

**Вывод: эксперимент невалиден. Починить бакетирование и перезапустить.**

И самое важное: результат **выглядит как победа** — лифт 20% с p-value 0,00007. Аналитик, пропустивший проверку SRM, раскатил бы фичу, которая ничего не даёт. Отличие от `exp_001` не в силе эффекта, а исключительно в валидности.

Про сегментный разбор: соблазн сказать «внутри десктопа эффект настоящий, там p = 0,004». Не работает. Группы внутри десктопа тоже несопоставимы по размеру (4 006 против 9 332), и сломанный бакетер мог коррелировать не только с устройством. Спасать данные сломанного эксперимента нельзя.

### exp_002 — payment_retry_ui

Окно 30 марта — 24 мая. Единица — игрок. Первичная метрика — доля игроков с успешным депозитом. Гипотеза: кнопка «Попробовать другой способ» на экране отказа платежа поднимет долю успешных депозитов.

| | control | treatment |
|---|---|---|
| игроков | 92 | 70 |
| с успешным депозитом | 71 | 49 |

**SRM:** 56,8% на 43,2%, χ² = 2,99, p = 0,084 → формально не отвергаем. Но перекос выглядит подозрительно, и это повод сказать отдельно: **на 162 наблюдениях проверка SRM почти не имеет мощности.** Отсутствие сигнала здесь не гарантирует, что рандомизация работала.
**Первичная метрика:** 77,17% → 70,00%. Эффект **−7,17 пп**, 95% ДИ **[−20,91; +6,57]**, z = −1,032, **p = 0,302**.
**MDE** при n = 70: **19,86 пп** (26% относительных).
Чтобы обнаружить реалистичный эффект в 5 пп, потребовалось бы **1 105 игроков в группе** — в пятнадцать раз больше.

**Вывод: тест не измерил ничего. Это не отрицательный результат, а отсутствие результата.**

Доверительный интервал шириной 27 процентных пунктов накрывает и «стало хуже на 20 пунктов», и «стало лучше на 6». Никакое решение на таком интервале принять нельзя.

Правильная рекомендация: либо набрать выборку (по трафику это займёт около полутора лет — то есть тест невозможен), либо проверять гипотезу иначе: смотреть на данные платёжных попыток, где наблюдений в разы больше, либо тестировать на уровне попытки оплаты, а не игрока.

## Три вывода, ради которых существует этот проект

**Первый.** Результат, выглядящий как убедительная победа (`exp_003`: +20%, p = 0,00007), может быть полностью артефактом. Единственное, что его отличает от настоящей победы, — проверка SRM, которая делается за одну минуту и которую пропускают чаще всего.

**Второй.** Отсутствие значимости (`exp_002`) само по себе не означает отсутствия эффекта. Без MDE вывод «не работает» некорректен. Здесь MDE в четыре раза больше ожидаемого эффекта, то есть тест был обречён с самого начала — и это выяснилось бы за две минуты, если бы кто-то посчитал до запуска.

**Третий.** Валидация идёт до анализа. Не после, не «заодно», не «если будет время». Потому что человек, уже увидевший красивый лифт, найдёт способ объяснить неудобную проверку.

## Критерии приёмки

Обязательные:

- [ ] `unit_id` соединён правильно для каждого эксперимента с учётом `experiments.unit`.
- [ ] Первичная метрика посчитана из событий, определение зафиксировано.
- [ ] Guardrail-метрики предложены и обоснованы для всех трёх экспериментов.
- [ ] MDE посчитан для всех трёх при фактическом размере групп.
- [ ] SRM проверен **первым**, до анализа результата. Уровень значимости для SRM 0,001, и это обосновано.
- [ ] Балансировка по устройству проверена во всех трёх.
- [ ] Все эталонные числа воспроизведены.
- [ ] По `exp_001` вывод «раскатывать», с интервалом эффекта и проверенными guardrail.
- [ ] По `exp_003` вывод «невалиден, перезапустить». Явно сказано, что наивный анализ дал бы ложную победу.
- [ ] По `exp_003` объяснено, почему сегментный разбор не спасает сломанный эксперимент.
- [ ] По `exp_002` вывод «тест ничего не измерил», а не «эффекта нет». Приведён MDE и требуемый размер выборки.
- [ ] По `exp_002` отмечена низкая мощность самой проверки SRM на такой выборке.
- [ ] Сегментный анализ сделан с поправкой на множественность.
- [ ] Симуляция подглядывания проведена, цифра приведена.
- [ ] Три документа по структуре из части 6 теории.

Желательные:

- [ ] Посчитан эффект `exp_001` в деньгах: сколько дополнительных регистраций и депозитов даст раскатка на весь трафик.
- [ ] Проверено, есть ли в `exp_001` признаки эффекта новизны: сравнить эффект по неделям.
- [ ] Для `exp_003` восстановлена вероятная причина поломки бакетирования по корреляции перекоса с признаками.
- [ ] Проверена целостность разметки: сравнить объёмы всех типов событий между группами.
- [ ] Предложен план поэтапной раскатки `exp_001` с критериями остановки.
- [ ] Для `exp_002` посчитано, дал ли бы результат анализ на уровне платёжных попыток вместо игроков.
